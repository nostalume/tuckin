# tuckin 行为规范

[English](spec.md) · [使用教程](../README.zh-CN.md) · [架构](architecture.zh-CN.md)

本规范定义仓库格式、命令效果和可观察的失败行为。教程中的示例使用这里的规则。

<a id="repository"></a>

## 仓库与目标位置

操作现有仓库的命令从当前目录向上寻找最近的 `tuckin.toml`。标记缺失时继续向上，标记不可读、类型不是普通文件或搜索用尽时返回 `E-G1`。配置是 UTF-8 TOML，顶层可用字段为 `schema`、`map`、`ignore`、`data`、`identity_file` 和 `recipients`，均可省略。`schema` 若存在必须是整数 `1`。配置、映射条目和忽略规则中的未知字段返回 `E-G1`。普通的 `edit tuckin.toml` 只要求标记是普通文件，可以打开内容无效的配置。

| 声明 | 规则 |
| --- | --- |
| 源路径 | 仓库相对 UTF-8 路径，至少两段。空段、`.`、`..`、绝对路径及开头的 `~` 无效。以 `@` 开头的段最多出现一次，必须紧跟 `home`，后面还需至少一段。 |
| 映射键 | `home` 等根键，或以 `home/@anchor/` 开始且至少三段的前缀。整段匹配，忽略大小写。最长的匹配键决定采用哪一行。 |
| 平台字段 | Windows 选择 `win`。Linux 和 macOS 优先选择 `linux` 和 `macos`，其次使用同一行的 `posix`。其他非 Windows 系统使用 `posix`。选中行没有平台值时返回 `E-A1`。 |
| `dirs:NAME[/suffix]` | 解析系统目录后附加可选的字面后缀。名称限于 `home`、`config`、`data`、`cache`、`programdata`、`documents`。所需目录不可用时返回 `E-G1`。 |
| `abs:PATH` | 使用给定的绝对路径，无 shell 或环境变量展开。 |
| 相对值 | 以当前平台的最长真前缀键为基准。根键要求 `dirs:` 或 `abs:`。相对值和 `dirs:` 的后缀要求非空路径段，且不含 `.` 或 `..`。 |

源路径未匹配的后缀按字面附加。带锚点的源路径要求匹配的锚点键。没有映射或映射为空时，`home` 指向用户主目录，`etc` 在 Windows 指向 ProgramData，在 POSIX 指向 `/etc`。非空映射表提供完整声明。翻译后的路径须能由平台表示，单段在 Windows 最多 255 个 UTF-16 码元，在 POSIX 最多 255 字节。Windows 还拒绝保留字符、设备名和末尾带点或空格的段（`E-P1`）。

文件扫描跳过根目录中以 `.git` 开头的名称以及 `tuckin.toml`、`tuckin.tags` 和 `scripts`，Windows 上对这些名称的比较忽略大小写。扫描不进入源目录链接。部署源必须是普通文件。仓库布局禁止仅大小写不同的重复项和符号目标冲突。比较各平台的符号目标时应用平台忽略条件，活动标签为空。当前机器还会解析现存目标父目录及其别名，拒绝重复的实际位置、被另一条目当作父目录的位置、仓库内部的位置，以及身份文件保留的位置。已存在的最终目标必须是普通文件，链接等其他对象返回 `E-T1`。

命令行选择器使用仓库路径，接受两种分隔符并去除开头的 `./`，拒绝 `..`。前缀按完整路径段匹配，区分大小写。每个选择器都须匹配，合并结果保持仓库路径顺序。精确文件操作要求给出文件路径。选择器限定读取内容的范围，实际位置验证仍覆盖当前机器的全部入选条目。

## 忽略规则与模板数据

标记旁的 `tuckin.tags` 使用 UTF-8。忽略开头的 BOM。每行取第一个 `#` 之前的文本，裁去首尾空白。空行无效。文件缺失表示没有活动标签。不可读或非普通的标签文件返回 `E-G1`。

每条 `[[ignore]]` 提供 `paths`，可选一个 `platform` 与一组 `tags`。平台匹配且规则中的全部标签都激活时，这条规则才生效。省略的条件无约束。`posix` 匹配所有非 Windows 平台。仓库路径被任何生效规则的 glob 匹配即排除，脚本同样适用。目录匹配只排除该路径，子项须通过 `notes/**` 等模式一并排除。

`[data]` 接受字符串、整数、浮点数和布尔值，以及名为 `@NAME` 的一层覆盖表。按默认值、当前 OS 层（`@windows`、`@linux`、`@macos` 或当前 OS 名称）、活动标签文件顺序合并。同一层按首次出现位置生效，后层按键覆盖前层。不存在的层无贡献。数组、日期、嵌套层或无效层形状返回 `E-G1`。

非 UTF-8 源，或不含 `{{` 的 UTF-8 源，按原字节复制。解析文本源时接受标量引用、注释和下表中的函数。缺失输入、不支持的语法和函数求值错误返回 `E-R1`。渲染执行一遍，输出原始文本。

| 语法 | 含义 |
| --- | --- |
| `{{name}}` | 从合并后的数据读取标量。 |
| `{{env "NAME"}}` | 读取已定义的 UTF-8 环境变量。模板应使用公开值。 |
| `{{which "program"}}` | 从可执行文件搜索路径解析程序。 |
| `{{join "a" "b"}}` | 用平台的路径分隔符连接两个或更多参数。 |
| `{{! 注释 }}` | 不产生输出。 |

函数参数为裸数据键，或字符串、整数、布尔字面量。键可以引用任意受支持的标量。`{{` 正前方只有一个反斜杠时，花括号按字面输出。有两个或更多连续反斜杠时减少一个，标签仍生效。值和函数的输出直接作为字节使用。相同规则适用于入选脚本。

## 字节补丁

含 `patch` 块的源修改一个已存在的目标文件，按字节搜索。块外只允许文本和注释，均无输出。块体是文本模板或一个独占的密封块。空块体清空其管理范围，非空模板渲染为空时报错。独占一行的块标签行会移除，结束标签前的内容换行保留。

| 形式 | 必填参数 | 可选参数 |
| --- | --- | --- |
| `patch "between"` | `after`、`before` | `name` |
| `patch "line"` | `prefix` | 成对的 `after` 与 `before`、`insert_before`、`name` |

参数须为非空字符串字面量。`after` 与 `before` 必须不同。名称在源内唯一、区分大小写，只用 ASCII 字母、数字、下划线和连字符。行前缀与插入锚点均须为不带缩进的单行前缀，二者互不为前缀。行补丁块体不能含 CR 或 LF。非法参数或块体形状返回 `E-R1`。

- `between` 在输入中唯一匹配 `after`，再从该匹配末尾起唯一匹配 `before`。替换两者之间的区间，区间可为空。两个标记均保留。
- `line` 的可选标记对采用同一搜索规则，范围须由完整的行构成。以 LF 分行，CRLF 识别为一个行尾。跳过行首空格和制表符，再匹配前缀。唯一命中时保留缩进、前缀和行尾，替换整个后缀。多处命中时报错。没有行首命中时，若前缀出现在行内则禁止插入。其余情况下，`insert_before` 可以在范围内唯一匹配的锚点行之前插入，沿用该行缩进和行尾。锚点行没有行尾时使用文件第一个行尾，文件无换行时用 LF。
- 所有编辑在同一原始输入上定位。编辑区间不得相交，还必须保留定位所需的范围。同一位置的行插入按声明顺序。输出有变化时需再次定位整组补丁，且不得需要追加字节改动。

目标缺失、必要定位缺失或有歧义、搜索范围无效、编辑相交或输出不收敛，均返回 `E-PA1`。发布时原始目标摘要必须仍匹配。

## 密封与身份

`seal` 块无参数，存储二进制 age 密文的规范单行 Base64，占据整份源声明，或独占一个补丁块体。非法块或非法 Base64 返回 `E-R1`。空块可显式填充，部署计划拒绝空块。任一密封块使整个目标成为私有文件，详细差异隐藏其内容和字节数。补丁定位文本是公开的。

新密文使用 `recipients` 中非空的一组有效 age X25519 公钥，重复密钥折叠。缺少收件人时无法生成新密文。解开已有密文只依赖匹配的本地身份。身份路径优先级为 `AGE_IDENTITY_FILE`、`identity_file`、`~/.config/age/keys.txt`。配置中的路径为绝对路径，或 `~/` 加正常路径段。`AGE_PASSPHRASE` 解锁已有的口令保护身份。身份缺失或不可用、口令缺失或错误、身份不匹配、空密封块和损坏密文，分别具有可区分的 `E-E1` 原因。

`init --key` 使用同一身份位置。身份缺失时私有创建，已有身份不可用时返回错误并保留该文件。收件人尚未声明且身份只含一把不同的密钥时，基于所读配置绑定其公钥。多把不同密钥需要显式选择。已有收件人时，命令报告本机公钥供显式更新，保留收件人声明。身份已创建但配置发布失败时，下次可复用该身份。修改收件人只作用于新密文。新建密钥无法打开写给已丢失身份的旧密文。

成功的私有发布以所有者读写权限创建或替换整个目标。POSIX 使用 `0600`，Windows 的本地 NTFS 使用受保护的所有者访问 DACL。计划阶段验证私有写入能力，已知不支持的目标在发布前返回 `E-P1`。当字节一致但权限不足时，仍会计划替换。

| 操作 | 选定字节与效果 |
| --- | --- |
| `add --encrypt PATH…` | 将现有普通目标采纳为新整文件密封块。需要收件人，可在无需打开身份的情况下运行。 |
| `edit PATH --seal[=NAME]` | 从隐藏输入或原始标准输入读取非空字节，密封选中的块体。 |
| `absorb PATH --seal[=NAME]` | 从现有目标或选中的目标范围读取非空字节。 |
| `edit PATH --rekey` | 打开源中所有已填充的密封块，以当前收件人重新加密。 |
| `absorb PATH --rekey` | 从目标采集所有已填充密封块对应的字节，以当前收件人重新加密，无需旧身份。 |
| `edit` 或 `absorb` 同时指定两项 | 从对应的输入重新加密选中的块体，无需打开旧密文。 |

显式密封与轮换需要一个精确的源路径。裸 `--seal` 选择整文件密封块或文件内唯一补丁，`--seal=NAME` 选择命名补丁。显式密封要求补丁块体是字面文本或密封块。修改已填充的密封块时，若没有 `--rekey`，命令解开旧密文并在字节相同时保留它。普通回收也遵循同一保留规则。输出为 `sealed` 或 `unchanged`，带路径及选中的补丁名（若有）。单独使用 `--rekey` 输出 `rekeyed` 与路径。POSIX 支持用外部编辑器在受保护的会话中编辑密封源。Windows 使用显式密封或轮换操作。

修改收件人或重新密封工作树时，旧提交会保留历史密文。旧密钥不可用时，恢复需要一个匹配的身份、可信的已部署副本，或原始明文。

<a id="deployment"></a>

## 计划与发布

`status`、`diff` 和 `apply` 共用一个计划。目标现有字节与上次确认的内容一致，或者用户以 `--overwrite` 选择其精确源路径，才允许替换。记录须能用当前本机密钥验证。缺失、不可读或验证失败的记录不能授权覆盖。整文件可创建缺失目标，补丁可在其定位器允许时插入缺失的行，或填充已匹配的两处边界之间的空区间。补丁独立比较各范围，范围外的修改不会阻止部署。密文字节相同时仍可能需要修复访问权限。

计划存在覆盖冲突时，目标写入数为零，脚本不启动。创建时要求位置为空，替换时要求目标与规划时读取的整文件摘要一致。`--overwrite` 也遵守此规则。摘要复核与重命名是两个操作。发布开始后若发生错误，已完成的写入会保留并报告。

本机记录只保存带密钥的指纹，按仓库、解析后的目标位置和所管理的范围区分。`apply` 可登记已一致的内容或成功发布的内容。普通 `absorb` 可登记已成功回收并能原样部署的值。修改管理内容前先撤销旧记录。若中断发生在保存新记录之前，下次运行会将不同的内容判作未经确认。`diff` 和 `status` 仅读取记录。记录位于本机数据目录的 `tuckin/deployments-v1`，可用 `TUCKIN_STATE_DIR` 指定仓库外的绝对基础目录。管理目标不能占用记录目录。

`add` 要求明确、可映射、非元数据的文件路径，目标存在且为普通文件，源须缺失。整批先准备，再逐项写入。普通 `absorb` 将目标的变化写回现有源，可写回整份字面文件或符合条件的补丁范围，保留定位文本和未变化的密文。缺失目标与未填充密封块会跳过。已有密文因目标缺失未能更新时报告 `unresealed`。无法表示为字面源的生成块体返回 `E-AB1`。准备失败不会发布，发布阶段失败保留先前已写的源。

<a id="scripts"></a>

## 脚本执行

脚本是根目录下 `scripts/` 内的直接子文件。入选目录与非普通文件均为错误，忽略规则照常适用。扩展名匹配忽略大小写。

| 扩展名 | 派发 |
| --- | --- |
| `.sh` / `.bash` | `sh` / `bash` |
| `.lua` | 独立的 `lua` |
| `.ps1` | PowerShell 7，使用 `pwsh -NoProfile`，Windows 上另加 `-ExecutionPolicy Bypass` |
| `.py` | 先使用绝对路径的活动虚拟环境，再从可执行文件搜索路径查 `python3`、`python`，最后在 Windows 尝试启动器列出的本地 Python 3 安装 |
| 其他 | POSIX 直接执行，Windows 接受 `.exe`，并通过命令处理器执行 `.cmd` 和 `.bat`。 |

显式解释器直接读取脚本文件，依据扩展名选择，不依赖 shebang。Windows 上的 shell 要能处理原生路径。必需解释器不可用时在文件发布前返回 `E-P1`。所有文件发布后，脚本以文件名的字节顺序在仓库根目录运行，继承调用账户的权限和环境。某个脚本失败会停止后续脚本，并保留已完成的效果。文件选择器不会关闭脚本阶段，`--no-scripts` 会跳过包括读取脚本目录在内的整个阶段。

文件名以 `gate-` 开头的脚本，在仓库位置、Git 状态、脚本名、派发方式和渲染字节相同时可复用成功记录。只有缓存未命中的脚本需要解释器。整个脚本阶段成功后才记录新结果。缓存不可用、无效或不可写时可能重跑。可用 `TUCKIN_CACHE_DIR` 选择仓库外的缓存目录。启用脚本的部署每次都运行普通脚本。

<a id="cli"></a>

## 命令与诊断

| 命令 | 范围与结果 |
| --- | --- |
| `init [--from SOURCE]` | 在空的当前目录初始化。普通 `init` 创建 `tuckin.toml`。只有 `--from` 要求 `git` 可执行程序，可传入 Git URL 或本地仓库路径。克隆和凭据由 Git 处理，发布前验证克隆的仓库布局。`--from` 与 `--key` 互斥。 |
| `init --key` | 使用最近的现有仓库。准备本机身份，并按[密封块与身份](#seals)初始化或查看收件人策略。 |
| `status [PATH…]` | 以 TSV 输出 `create`、`overwrite`、`repair`、`blocked` 或 `unchanged` 及路径。额外的 `?` 行列出未声明的相邻路径。非零忽略数针对整个扫描。 |
| `diff [PATH…]` | 重定向时以 TSV 输出待写项和受阻项。终端显示总数及最多六个路径。无差异时输出为空。 |
| `diff --patch PATH` | 预览一个精确源文件。正文最多 24 行、每行 76 列。每侧输入最多 64 KiB 和 4096 行，去除相同首尾后最多比较 65,536 个单元。二进制、密文及超限内容省略正文。 |
| `apply [--no-scripts] [--overwrite] [--list \| --patch] [PATH…]` | 发布文件，再运行启用的脚本。`--overwrite` 要求精确文件路径。终端显示最多六个已发布路径。重定向的默认输出保留 `created`、`overwritten`、`unchanged` 和 `bytes`。`--list` 对每个实际发布项输出 `create`、`overwrite` 或 `repair` 及源路径。`--patch` 显示一个精确文件实际写入的短片段。失败时，已完成的发布回执写到标准错误。 |
| `add [--encrypt] PATH…` | 将已有目标采纳为新源。 |
| `edit [PATH…]` | 启动 `EDITOR` 所指的可执行程序，不解析 shell 参数。默认路径为 `tuckin.toml`。显式密封操作见上文。 |
| `absorb [PATH…]` | 从目标收集变化到源。显式密封操作见上文。 |

`status`、`diff`、`apply` 和 `absorb` 在省略路径时选择全部入选条目。结果写入标准输出，诊断写入标准错误。成功返回 0，成功的 `diff` 有差异（包括受阻项）时返回 1，用法或操作失败返回 2。带编号的诊断包含对象及 `missing`、`current`、`why`、`fix` 字段。部分用法或 I/O 错误只提供无编号的消息。

| 编号 | 错误所属范围 |
| --- | --- |
| `E-G1` | 仓库标记、配置、标签或数据 |
| `E-A1` / `E-A4` | 源路径、映射或锚点形状 |
| `E-I1` / `E-T1` | 位置冲突或所需普通对象缺失 |
| `E-R1` / `E-PA1` | 源形状、渲染或无法定位及应用的补丁 |
| `E-AB1` | 目标字节没有合法的源表示 |
| `E-E1` / `E-P1` | 密封或身份错误，或缺少平台能力 |
